# RSML Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox syntax for tracking.

**Goal:** Import and faithfully re-export RSML documents, and independently export current Root Tracker results without changing tracking behavior.

**Architecture:** Imported documents own immutable original bytes and read-only parsed views. Tracked exports use a separate geometry adapter and opt-in entry points. Export-only pixel snapshots survive cache reloads without repopulating the `colored_samples` field used by tracking.

**Tech Stack:** Python, standard-library XML/Expat, NumPy/OpenCV, PySide6, unittest.

**Spec:** `docs/superpowers/specs/2026-09-26-rsml-design.md` (approved in conversation).

## Global Constraints

- Existing Root Tracker processing, measurements, CSV output, and image workflows take precedence.
- Imported roots must never initialize or influence tracking.
- Preserve the original XML bytes when saving imported documents.
- Never implicitly merge imported metadata into newly tracked geometry.
- Export requires current tracking results; existing CSV actions and CLI defaults remain unchanged.
- Preserve unrelated working-tree changes and do not depend on experiment directories in automated tests.

## Review Focus

- Old caches have no export geometry: fail with a retracking instruction, without silently changing tracker state.
- Evicted series have no arrays: reload into an export-only copy, preserving active GUI state.
- Duplicate image basenames and hostile group names: generate distinct safe output paths beneath the chosen directory.
- UTF-16 XML and namespaced vendor elements: preserve bytes and reject DTDs using parser callbacks, not text matching.
- Parallel CLI workers return statistics only: export inside the owning worker while geometry is available, propagating export failures.
